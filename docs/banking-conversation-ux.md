# 银行开户与信用卡对话体验

## 目标

让用户在“开户 / 借记卡”和“信用卡”之间不再被错误分流，同时保持亲切、稳定、简洁的服务语气。事实与来源仍需在后台完整留存，但聊天正文不呈现成科研文章。

## 分流规则

- 明确账户意图：开户、银行账户、储蓄卡、借记卡、提款卡、往来账户、支票账户等，直接进入开户流程。
- 明确信用卡意图：信用卡、Visa 卡、Mastercard、年费、积分、里程、返现、开卡优惠等，直接进入信用卡流程。
- 模糊说法：银行卡、办张卡、开卡、申卡、哪张卡、卡推荐等，在没有更多上下文时不猜测，先让用户选择；如果会话中只有一个明确的银行场景，则沿用该场景。
- 同时明确提到开户和信用卡时，两个场景分别回答，不要求用户二选一。
- 本轮明确表达优先于历史主题和模型补充判断：“账户／开户／借记卡”可从信用卡切回账户，“信用卡／年费／积分”也可从账户切到信用卡。
- 模型只能补充规则没有识别到的意图，不能在本轮已明确“账户”时再附加信用卡意图，反之亦然。

推荐交互：

> 没问题，我先确认一下：您这次更想了解哪一类？
>
> [开银行账户／办借记卡] [申请／挑选信用卡]

这个选择只用于本轮路由，不写入用户长期资料。选择后再分别询问开户地区或信用卡申请地区。

## 语言风格

- 始终使用“您”，语气温和、自然，但不过度热情。
- 第一段先回答用户最关心的结论，再给两到五个短要点。
- 一轮最多问一个关键问题；能用按钮选择时，不让用户猜该怎么回答。
- 使用“给您的建议”“下一步”“温馨提示”等客户语言。
- 避免“根据数据库”“经检索”“证据表明”“综上所述”“参考文献”等系统或论文式表达。
- 不承诺审批结果，不把“常见做法”说成“硬性要求”。

## 来源展示

- 回答正文不显示 `[1] [2]` 等行内编号，也不默认铺开参考文献列表。
- 官方页面放在回答底部的折叠入口“查看官方依据（N）”中，需要时再展开。
- 后台继续保存 citation、claim、版本和读取记录，便于审计与排错。
- 多个官方来源互相冲突时，仍明确提示差异，不替用户或银行做未经证实的取舍。

## 验收示例

| 用户说法 | 预期行为 |
| --- | --- |
| 我想办张卡 | 弹出两类选择，不直接推荐信用卡 |
| 香港借记卡怎么开 | 进入香港开户流程 |
| 香港信用卡推荐 | 进入香港信用卡流程 |
| 开户和信用卡都需要吗 | 分开回答两个场景 |
| 信用卡开卡优惠 | 进入信用卡流程，不误判为开户 |
