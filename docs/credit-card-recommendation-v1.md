# 信用卡推荐 v1

## 用户流程

```text
申请地区、年龄、年收入
→ 申请门槛过滤
→ 还款方式
→ 主要消费场景
→ RDS 产品读取
→ 主卡排序
→ 按场景缺口选择最多两张补充卡
→ 最多三张符合门槛的免年费备选
→ 数据质量门控
```

每轮最多展示两个追问。结构化选项会明确提示用户保存到画像，点击后直接确认写入 Profile；
自由文本里抽取出的新信息仍只生成 Profile 变更提案。

资产区间已经登记为可用字段，但当前 RDS 的 `CARD_ELIGIBILITY_RULE` 没有资产类规则，因此流程不会主动询问。以后产品出现资产、存款或抵押门槛时，再由规则触发。

## RDS 数据

读取现有五张表：

| 表 | 用途 |
| --- | --- |
| `CREDIT_CARD` | 产品、市场、状态、数据质量、官方链接和核验时间 |
| `CARD_ELIGIBILITY_RULE` | 年龄、收入、学生身份、银行关系等硬门槛 |
| `CARD_REWARD_RULE` | 场景奖励、奖励类型、奖励率和上限 |
| `CARD_FEE` | 年费、境外交易费和年费减免条件 |
| `CARD_BENEFIT` | 休息室、保险、商户优惠、双币结算等权益 |

Agent2 使用 `agent1.storage.read_session()` 建立只读事务，不会在推荐请求中执行建表 DDL。

## 排序规则

1. 明确不满足年龄、收入或其他必要条件的卡直接排除。
2. 已满足全部公开门槛的卡排在门槛信息仍不完整的卡之前。
3. 主卡按场景奖励、场景覆盖、年费、境外消费费用、门槛确定性和数据质量评分。
4. 补充卡必须覆盖主卡没有覆盖的用户场景，并且已经满足门槛。
5. 免年费备选必须满足门槛，排除已经作为主卡或补充卡的产品，最多展示三张。

积分和里程缺少统一兑换价值时只计算相对匹配分，不把它们伪装成现金净收益。

## 风险门控

- 用户可能分期或保留余额时，流程停止奖励排序。当前 RDS 没有 APR、分期利率和免息期，无法可靠比较借款成本。
- `answered` 要求所有展示产品均为 `verified`，带官方 URL，并在 24 小时内完成核验。
- 当前 RDS 的十张香港信用卡全部是 `synthetic`，且缺少官方链接和核验时间，因此实际运行结果是 `needs_verification`，回答中会显示“模拟推荐”。
- 最终审批由发卡机构决定；门槛判断不会表述为保证获批。

## 信用卡追问与 Profile

信用卡流程优先复用当前 Session 唯一绑定的 Profile。门槛信息缺失时使用结构化选项：

1. 申请地区；
2. 年龄门槛区间；
3. 按 RDS 当前产品最低收入规则动态生成的收入区间；
4. 还款方式；
5. 最多三个主要消费场景。

用户明确点击的选项直接确认为 Profile 事实。收入、还款方式和银行关系等易变化字段保存
`confirmed_at` 与 `expires_at`；过期值读取为 `stale`，领域流程必须重新询问。
