# 信用卡推荐 v1（简版流程规范）

> 完整系统描述（数据模型、引擎算法、分层奖励计算、组合规则）见
> [credit-card-recommendation-v2.md](credit-card-recommendation-v2.md)；本文保留为流程与保证项的简版规范。

## 用户流程

```text
申请地区、年龄、年收入、香港居民资格
→ 检查公开收入门槛
→ 收入不足且产品支持资产审核时，询问可证明资产区间
→ 给出公开门槛 / 资产个案审批判断
→ Premier 资格路径（现有客户 / 可维持 HK$1,000,000 TRB 后升级 / 不适用）
→ 还款方式
→ 主要消费场景及优先级
→ 每月信用卡消费区间、奖励偏好
→ RDS 产品读取
→ 主卡排序
→ 按场景缺口选择最多两张补充卡
→ 最多三张符合门槛的免年费备选
→ 数据质量门控
```

每轮最多展示两个追问。结构化选项会明确提示用户保存到画像，点击后直接确认写入 Profile；
自由文本里抽取出的新信息仍只生成 Profile 变更提案。

资产问题按产品资格路径触发。收入明确达到公开门槛时不询问；收入不足、产品允许提交最近三个月银行资产证明时，询问可证明资产区间，并将结果标记为需要 HSBC 个案审批。

## RDS 数据

读取现有六张表：

| 表 | 用途 |
| --- | --- |
| `CREDIT_CARD` | 产品、市场、状态、官方链接和核验时间 |
| `CARD_ELIGIBILITY_RULE` | 资格路径；同一路径内条件为 AND，不同路径为 OR，可返回公开门槛符合或需银行个案审批 |
| `CARD_REWARD_RULE` | 场景奖励、奖励类型、奖励率和上限 |
| `CARD_FEE` | 年费、境外交易费和年费减免条件 |
| `CARD_BORROWING_TERM` | APR、免息期、分期示例、适用性及逐条官方来源 |
| `CARD_BENEFIT` | 休息室、保险、商户优惠、双币结算等权益 |

Agent2 使用 `agent1.storage.read_session()` 建立只读事务，不会在推荐请求中执行建表 DDL。

## 排序规则

1. 明确不满足年龄等硬门槛，或所有公开及个案审批路径均失败的卡才排除。
2. 收入不足但可提供本人资产证明的卡继续参与权益排序，并标记为需要银行个案审批。
3. 先按门槛状态排序（符合公开门槛 > 需个案审批 > 资料不足），资料不足的卡不会仅凭高奖励压过已确认符合门槛的卡。
4. 同一门槛状态内估算 `年度奖励现金价值 − 两年观察期的年化年费 − 对应消费场景的外币手续费`。金额计算使用用户月消费区间、场景权重、奖励率和奖励上限。
5. 积分只有存在有来源的现金等价值时才换算为港币；里程保留原单位，用户明确偏好里程时才使用里程数量排序。
6. 两张卡的年度净值差异不超过 5% 时，视为估算误差范围内并列，再比较场景权益、覆盖度和数据完整度。
7. 结果保留 RDS 完整候选排名、每项金额、门槛状态、缺失资格字段，以及产品库总数 / ACTIVE 数 / 过滤数。
8. 用户选择消费场景的顺序代表重要程度：三个场景依次使用 50% / 30% / 20%，两个场景使用 60% / 40%。“指定零售商户”不等同于所有网购。
9. 永久免年费与限时年费豁免分别计算；双币卡的人民币/澳门币费用优势只用于内地及澳门场景，不扩张为所有境外币种免费。
10. 补充卡必须覆盖主卡没有覆盖的用户场景，并且已经满足门槛。
11. 免年费备选必须满足门槛，排除已经作为主卡或补充卡的产品，最多展示三张。

积分和里程缺少统一兑换价值时只计算相对匹配分，不把它们伪装成现金净收益。

## 风险门控

- 用户可能分期或保留余额时，流程先展示有官方来源的 APR、免息期和分期成本；资料不完整时停止给出确定推荐。
- 借款条款逐条保存官方 URL、生效日和核验时间，不使用产品级 `data_status` 推断整张卡的数据质量。
- `answered` 要求所有展示产品带官方 URL，并在 30 天内完成产品字段核验；未逐项核验的奖励和年费会触发 `needs_verification`。
- 最终审批由发卡机构决定；门槛判断不会表述为保证获批。

## 信用卡追问与 Profile

信用卡流程优先复用当前 Session 唯一绑定的 Profile。门槛信息缺失时使用结构化选项：

1. 申请地区；
2. 年龄门槛区间；
3. 按 RDS 当前产品最低收入规则动态生成的收入区间；
4. 产品将香港居民列为基本条件时，确认香港居民资格；
5. 单独询问 Premier 资格路径：现有 Premier 客户并满足卡片关系结余、可维持 HK$1,000,000 TRB 并愿意先升级，或不适用；年收入不用于推断 Premier 身份；
6. 收入路径不满足时，询问能否提供最近三个月银行资产证明及可证明资产区间；
7. 还款方式；
8. 按重要程度选择最多三个主要消费场景；
9. 每月信用卡消费区间及返现 / 积分 / 里程偏好。

用户明确点击的选项直接确认为 Profile 事实。收入、还款方式和银行关系等易变化字段保存
`confirmed_at` 与 `expires_at`；过期值读取为 `stale`，领域流程必须重新询问。
